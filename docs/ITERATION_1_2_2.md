# 1.2.2 页面与登录修改

这次继续处理前一版的四处问题：新版页面流程、旧版成绩与学分、自动登录、正式发布。只记录本轮实际代码；学校数据和用户的课程编辑不改写成演示内容。

| 对应截图 | 修改 | 主要文件 | 当前验证 / 仍需确认 |
| --- | --- | --- | --- |
| IMG-04、05、09、15 | 新版首页围绕今日课程、课程详情和同步进度整理；个人页直达同一套课程设置、文件与登录入口 | `CampusPages.kt`、`MainActivity.kt`、`ScheduleRoute.kt` | 编译与正式打包结果写入根目录验证记录；实机页面和返回流程由用户验收 |
| IMG-07、09 | 新版学期学分可进入该学期成绩，刷新由应用任务继续，成绩优先读取缓存 | `AcademicGradesRoute.kt`、`CampusNavigation.kt`、`ScvtcRuntime.kt` | 需要用户核对真实成绩、学分口径与筛选行为 |
| IMG-07 | 旧版成绩增加未通过筛选，官方有目标时显示学分进度，学期入口可查看对应课程 | `AcademicActivity.kt` | 只展示真实接口返回；毕业资格仍以学校审核为准 |
| IMG-01、09、15 | 两版原生账号密码表单接入后台 CAS，保存加密凭据，会话过期自动恢复并继续读取 | `ScvtcLoginActivity.kt` / `LoginActivity.kt`、`CasAuthManager.kt`、`OfficialLoginMemory.kt` | 不用登录 URL 判断成功；学校登录、重启和自然过期仍需用户确认 |
| IMG-02、03、04、06、11、14、16、17 | 页面继续使用现有统一控件和壁纸；原有底栏、折射、色散、弹簧与可调参数保留 | 现有玻璃与外观组件、`CampusQuickActions.kt` | 本轮不测量帧率、不连接手机、不自动降级视觉效果 |

原生登录任务在应用中运行，页面退出不会取消认证；用户主动退出会取消任务。新版切换账号保留各自的加密凭据和离线记录。学校额外验证时才显示官方补充认证页面，认证失败不删除缓存。

两版沿用原包名、签名、数据库和密钥别名。云服务继续暂停，AI 仍需用户自己配置服务。新版插件平台校验的同步内容见 `PLUGIN_PLATFORM_3_6.md`。

本轮仅执行必要的编译、正式发布 Lint 和安装包核对，不执行自动化功能测试、手机调试或性能测试。各项是否通过，以本次构建后生成的 `VERIFICATION.md` 与 `BUILD_PROVENANCE.json` 为准。旧报告不算本次验证。
