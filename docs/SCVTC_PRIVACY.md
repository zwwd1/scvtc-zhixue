# 隐私与加密

| 内容 | 保存方式 | 分享与备份 |
| --- | --- | --- |
| 学校密码、表单绑定、可恢复 Session、认证头 | Android Keystore 密钥和 AES-256-GCM，账号作为关联数据 | 不写入 Git、日志、APK 明文资源或普通导出 |
| 服务 JSON（成绩、查询、要求） | 账号/学期/模块关联的 AES-GCM；旧明文缓存成功同步后替换 | 不公开原文；缓存失败保留最后成功结果 |
| 普通课程和作息 | 应用私有目录与 Room，按账号/学期隔离 | 系统自动云备份和设备迁移关闭；仅主动导出需要的数据 |
| 原生插件凭据、API Key | 专用安全存储及插件权限机制 | 不进入本项目公开源码或抓包报告 |
| APK 与更新签名私钥 | 仓库外的开发者私有配置 | 不随源码和 APK 分发 |

普通 Room 课程记录不等于逐字段 AES 密文。登录凭据具有应用级加密；普通缓存依靠应用沙箱与 Android 设备存储加密。这里不把二者混称为“所有数据端到端加密”。解锁设备、被控制的系统和主动分享文件具有不同的保护边界。

只有允许的学校 HTTPS 来源、真实表单提交和匹配的学生身份 API 能确认长期登录凭据。暂存凭据也先加密，过期后清除；不同账号不能直接复用关联密文。网络故障和认证过期不清除最后成功的课表。

本校数据直接访问学校 CAS、JWXT 服务。云上传、云恢复和匿名统计暂停。插件仓库、项目更新和用户主动调用的其他功能仍可能访问各自服务，不声称整个 App 完全离线。

学校密码不会交给 GitHub、项目维护者或 AI 服务。公开诊断只保留版本、设备、错误类型和数据数量等必要摘要；不发布真实账号、Cookie、Token 或可恢复抓包。

安全退出清除相应账号的认证材料。清查询缓存与删除课表是不同操作。卸载或清应用数据会失去 Keystore 密钥，旧密文不能复制到另一台设备恢复，需重新登录。普通本地导出可能含课程信息，应按个人文件保管。

每次发布检查源码、APK 明文资源、报告和归档。如果发现凭据意外暴露，应更新学校密码并清除旧授权，不能把密码提交到 Issue。

生成角色与图标为公开项目素材；用户参考照片、支付原图、带真实数据的设备截图和新 APK 留在本机交付，不上传公开仓库。素材来源与处理方式见 [BRANDING_20261009.md](BRANDING_20261009.md)。
